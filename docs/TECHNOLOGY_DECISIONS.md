# Technology decisions

Phase 0 deliverable, written 2026-10-15. Each entry records the options considered, the choice and
why, and whether the choice is implemented. Decisions marked **approved 2026-10-15** were confirmed
by the project owner in the Phase 0 review. Earlier decisions are also logged in
[architecture.md](architecture.md) (section 9).

## Environment the decisions were made for

macOS (Apple silicon), **8 GB RAM**, about 12 GB free disk, Python 3.13 venv, Node for the console,
Homebrew Postgres 14 without PostGIS, no Docker daemon, no Neo4j, no Qdrant, no Tesseract, Ollama
0.40.4 installed on 2026-10-15.

## Decisions

| Area | Options considered | Choice | Why | Status |
|---|---|---|---|---|
| Frontend framework | Vite + React; Next.js | **Vite + React 18 + TypeScript** (approved 2026-10-15) | Already built and tested (249 unit tests, Playwright); single-page console served by demo-server; no server rendering need; one frontend only | Implemented |
| Styling and motion | Tailwind v4 + tokens; CSS modules; component kits | **Tailwind v4 with three-layer CSS tokens, Framer Motion** | Existing design system, light/dark tokens, reduced-motion support | Implemented |
| Backend | FastAPI; Django; Node | **FastAPI + Pydantic v2 + SQLAlchemy Core** | Existing services; typed validation; async I/O for STT/LLM calls | Implemented |
| Architecture | Microservices; modular monolith; reorganise into `apps/web`, `apps/api` | **Keep the existing monorepo of services plus demo-server as the single-process composition** (approved) | Working services and tests; demo-server gives a one-command local run; moving folders would risk breaking imports, Dockerfiles and CI for no functional gain | Implemented |
| Database | PostgreSQL; SQLite; Supabase | **SQLite for local development, PostgreSQL in Docker** (approved) | SQLite needs no server on an 8 GB laptop; the same code and migrations run on Postgres (complaints suite passed on a disposable Postgres 14, agent-run). Supabase adds a hosted dependency without need | Implemented |
| Migrations | Alembic; custom versioned runner | **Keep the custom versioned runner** (`schema_migrations`, migrations 1-8) (approved) | Already handles SQLite table rebuilds and Postgres constraint swaps with tests; idempotent; advisory lock on Postgres. Switch to Alembic only if a concrete need appears (for example autogenerated diffs across many tables) | Implemented |
| Authentication | Clerk; Auth0; self-hosted passwords; local one-time codes | **Clerk in production; local email + one-time-code sign-in for development only** (approved) | No passwords stored; Clerk verified server-side (RS256/JWKS). Local mode lets the full flow run without keys. **Gap:** no guard yet that refuses local mode in production, and demo-server falls back to local when Clerk is unset | Clerk: implemented, live **blocked**; local: implemented |
| Authorisation | Frontend role checks; backend RBAC | **Backend RBAC only**, roles from the database, allowlist/bootstrap re-evaluated per request | Requirement; the frontend only hides navigation | Implemented |
| Evidence storage | Local disk; S3-compatible object storage; database blobs | **Local disk behind a storage interface** (approved) | Works offline; object storage can be added behind the same interface. Not encrypted, not malware-scanned (documented limitation) | Implemented (local) |
| Text risk scoring | Rules only; ML only; rules + ML | **Rules + TF-IDF/logistic-regression script classifier (call-guard clf-v1)** | Explainable, fast on CPU, reused by complaints and live audio | Implemented |
| Category model | Transformer fine-tune; TF-IDF + LR with abstention | **TF-IDF + LR with abstention (category-v1), SHA-pinned** | Small, CPU-only, explainable; trained on **100% synthetic** data with a family-grouped held-out split (macro-F1 0.715 held out; the leaky random split is not used as the headline) | Implemented |
| Speech-to-text | faster-whisper; whisper.cpp; cloud STT | **faster-whisper (base, int8) local, whisper.cpp HTTP optional** | Offline, ~0.7-1.3 s per 4 s chunk here; Hindi forced with a romanised prompt for Hinglish | Implemented (live audio); not yet used for uploaded audio |
| OCR | Tesseract; PaddleOCR; cloud OCR | **Tesseract (local) when installed** | Free, offline, Hindi + English language packs available | **Blocked** (not installed) |
| LLM explanations | Local Ollama qwen2.5:3b; qwen2.5:1.5b; qwen2.5:0.5b; Gemini free API | **Ollama qwen2.5:0.5b, local only, explanations only** (owner choice 2026-10-15; approved) | 3B too heavy for 8 GB RAM. Gemini rejected: complaint text contains personal data, and the free tier may use submitted content to improve Google's products; it also conflicts with the no-cloud-LLM rule. The LLM never changes score, level or category; output is grounded and checked, and rejected text falls back to the rule explanation. Quality is weak (see findings) | Implemented (complaints); live audio still uses an ungrounded explainer |
| Vector search (Fraud DNA) | Qdrant server; Qdrant local/embedded mode; pgvector; FAISS | **Qdrant in local (embedded) mode first; server later** (approved) | No server process; same client API as a server. Embeddings: the cached `paraphrase-multilingual-MiniLM-L12-v2` (Apache-2.0, 458 MB on disk) is suitable for Hindi/English similarity, but `sentence-transformers` and `torch` are **not installed**; the lighter ONNX route through qdrant-client `fastembed` is the alternative to evaluate. Fallback: report "unavailable" (or TF-IDF similarity, clearly labelled) rather than invent matches | **Planned** |
| Graph intelligence | Neo4j; NetworkX + SQL | **NetworkX + SQL first; Neo4j optional adapter** (approved) | Neo4j needs a JVM server (heavy on 8 GB); NetworkX already powers graph_twin. Complaint links must be typed observed / inferred / confirmed with evidence | **Planned** for complaints (graph_twin is simulator-only) |
| Geospatial | PostGIS; SQL grid on lat/lon; H3 | **SQL grid over stored coordinates first; PostGIS optional** (approved) | Local Postgres 14 has no PostGIS; SQLite has none. The Docker image `postgis/postgis:16-3.4` can enable it later | **Planned** for complaints (geo_intel is simulator-only) |
| Maps | Leaflet + OpenStreetMap tiles; MapLibre; offline d3-geo | **Leaflet + OSM tiles, with the existing offline d3-geo map as fallback** (approved) | Interactive and light. Privacy: tile servers see the viewer's IP and the tile coordinates being viewed, never complaint records; documented on the page. Respect the OSM tile usage policy (low volume, attribution) | **Planned** |
| Rate limiting | In-process; Redis | **In-process per user/IP today; Redis when running more than one process** | Simple and tested; known limitation behind proxies and across replicas | In-process implemented |
| Background jobs | Inline; Redis-backed queue | **Inline today**; a durable queue when long jobs (audio transcription of uploads, indexing) are added | Analysis is fast enough inline | Inline implemented |
| Messaging (simulator) | Redpanda/Kafka; in-memory bus | **Redpanda in Docker, InMemoryBus in demo-server** | Existing | Implemented |
| CI | GitHub Actions | **GitHub Actions** (`.github/workflows/ci.yml`: lint and tests for every package, Dockerfile and markdown link checks, compose config) | Existing; run status on GitHub not checked from this machine | Implemented, run status unverified |
| Multi-agent orchestration | LangGraph; none | **None** until a use case needs it | No current requirement justifies it | Not adopted |
| Languages | 12 Indian languages; a smaller evaluated set | **English, Hindi, Hinglish first** (approved) | Only these have been evaluated (speech tests); more languages only with evaluation per language | Partial |
